# Выбор и настройка мониторинга в системе

## 1. Мотивация

Внедрение мониторинга необходимо для решения ключевых проблем бизнеса:

| Проблема                               | Цель мониторинга                                                                              |
|----------------------------------------|-----------------------------------------------------------------------------------------------|
| Рост жалоб клиентов                    | Выявление узких мест в системе                                                                |
| Просроченные заказы                    | Контроль времени обработки и отслеживание потерь                                              |
| Медленная загрузка MES                 | Диагностика производительности интерфейса                                                     |
| Потеря контрактов                      | Превентивное обнаружение проблем API                                                          |
| Накопление неиспользуемого функционала | Выявление неиспользуемых функциональностей для упрощения системы и исключения их из поддержки |

## 2. Выбор подхода к мониторингу

Для разных компонентов системы используем специализированные подходы:

| Подсистема        | Подход                 | Обоснование                     |
|-------------------|------------------------|---------------------------------|
| Базы данных       | USE                    | Контроль критичных ресурсов     |
| API-сервисы       | RED                    | Фокус на пользовательском опыте |
| Очереди сообщений | Четыре золотых сигнала | Надежность коммуникации         |
| Бизнес-процессы   | Кастомные метрики      | Отслеживание выполнения заказов |

## 3. Метрики для отслеживания

| Метрика                                  | Назначение                    | Ярлыки                                              |
|------------------------------------------|-------------------------------|-----------------------------------------------------|
| `Number of requests (RPS) for MES API`   | Нагрузка на расчет стоимости  | `service: mes-api`, `type: performance`             |
| `Response time (latency) for MES API`    | Время обработки 3D-моделей    | `service: mes-api`, `type: performance`             |
| `Number of dead-letter-exchange letters` | Проблемы в очередях сообщений | `service: message-queue`, `type: reliability`       |
| `Number of HTTP 500 for MES API`         | Критические ошибки расчетов   | `service: mes-api`, `type: error`, `severity: high` |
| `Memory Utilisation for MES API`         | Потребление памяти            | `service: mes-api`, `type: resource`                |
| `CPU % for MES API`                      | Нагрузка сервера              | `service: mes-api`, `type: resource`                |

### Бизнес-метрики

| Метрика                            | Назначение                       | Ярлыки                                        |
|------------------------------------|----------------------------------|-----------------------------------------------|
| `Order Processing Time`            | Полное время выполнения заказа   | `domain: order-management`, `type: business`  |
| `3D Model Calculation Duration`    | Время расчета стоимости          | `domain: pricing`, `type: performance`        |
| `API Response Success Rate`        | Доля успешных запросов           | `type: reliability`, `scope: api`             |
| `RabbitMQ Message Processing Time` | Скорость доставки сообщений      | `service: message-queue`, `type: performance` |
| `Feature Usage Frequency`          | Востребованность функций системы | `feature: <name>`, `type: usage`              |

## План внедрения

### Приоритет 1: Высокий

1. **Базовый мониторинг**
    - Развертывание Prometheus + Grafana
    - Настройка дашбордов для MES, CRM, магазина
    - Реализация алертинга по ключевым метрикам

2. **Трекинг заказов**
    - Мониторинг времени выполнения заказов
    - Отслеживание статусов между системами
    - Дашборд просроченных заказов

3. **Диагностика производительности**
    - Профилирование MES для поиска узких мест
    - Мониторинг очередей RabbitMQ
    - Внедрение кэширования данных

### Приоритет 2: Средний

4. **Масштабирование инфраструктуры**
    - Горизонтальное масштабирование MES API
    - Балансировка нагрузки
    - Мониторинг ресурсов БД

5. **Автоматизация процессов**
    - E2E-тестирование критичных сценариев
    - Непрерывная интеграция
    - Контроль качества кода

### Приоритет 3: Низкий

6. **Оптимизация API**
    - Throttling и rate limiting
    - Версионность API
    - Документация интерфейсов

7. **Пользовательский опыт**
    - Мониторинг производительности фронтенда
    - Lazy loading для MES
    - Оптимизация рендеринга

## Целевые показатели

По итогам внедрения ожидаем:

- Сокращение времени обработки заказов на 40%
- Уменьшение жалоб клиентов на 60%
- Повышение отказоустойчивости системы
- Улучшение масштабируемости инфраструктуры
- Создание метрик для идентификации неиспользуемого функционала
